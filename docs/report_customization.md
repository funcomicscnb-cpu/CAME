# Report Customization

The final report is designed to be readable as published output and easy to adapt for internal summaries or manuscripts without changing analytical results.

## Structure

Final reporting writes three groups of files under `results/final/`:

- `manifest/`: discovered outputs and missing-output warnings.
- `provenance/`: CAME version, runtime/tool versions, git status when available, timestamp, outdir, and parameter snapshot.
- `assets/`: compact stage, warning, candidate, enrichment, and asset-manifest tables used by the report.
- `report/`: HTML, Markdown, and CSS.

The HTML and Markdown reports include study profile context, status legend, provenance, parameters, stage completion, compact stage summaries, release checks, top candidates, top enriched gene sets, warning summaries, key output links, and limitations.

Study profile context is read from the profile `study` section and displayed as metadata only. Reporting labels can make outputs easier to interpret, but they do not validate biological correctness or add profile-specific analysis rules.

## Provenance

`bin/collect_run_provenance.py` records reproducibility metadata without requiring a git checkout or every optional tool to exist. Missing git metadata, unavailable R/Nextflow, or absent parameter snapshots are written as `WARNING` rows.

Paths in parameter snapshots are normalized to project-relative or results-relative paths when possible. Paths outside those roots are represented as external path placeholders so reports do not expose local machine-specific directories.

## CSS And Templates

The report renderer reads:

- `templates/came_report_template.html`
- `templates/came_report_template.md`
- `templates/came_report.css`

The published HTML links `came_report.css` relatively from `results/final/report/`. Edit the CSS for visual styling changes. Edit the HTML or Markdown templates only for structural wrapping; report sections are generated by `bin/render_final_report.py`.

Keep template changes reporting-only. Do not add biological interpretation rules, profile-specific assumptions, or new analysis steps in report templates.

## Stage Completion

Stage completion is a structural summary. It checks expected compact outputs and warning/error records:

- `completed`: expected compact outputs were present with no report-level warning counts.
- `warning`: expected outputs are partial or warning records were found.
- `missing_optional`: optional or upstream outputs were unavailable; report generation continued.
- `failed/error`: an error record was found and should be reviewed.

A missing stage does not mean the stage failed. It can mean the stage was not part of the run being summarized.

## Warnings

Warnings are grouped by stage first, then severity and source. Sources include missing expected outputs, release checks, validation reports, and `*_warnings.tsv` files. Release `WARNING` records are visible in the report but do not fail `final_report`; release `ERROR` records do fail after outputs are written.

## Publication Links

Use relative links from `came_final_report.html` or `came_final_report.md` to cite output files in publications or internal summaries. Recommended stable links include:

- `final/provenance/came_run_provenance.tsv`
- `final/provenance/came_parameters_snapshot.tsv`
- `final/assets/report_asset_manifest.tsv`
- `final/manifest/came_outputs_manifest.tsv`
- `final/release_checks/came_release_checks.tsv`

For manuscript supplements, include the report, CSS, provenance tables, asset manifest, and any linked result tables needed to support the claims.

## Limitations

- The final report does not validate biological correctness.
- Provenance records available local metadata and dependency versions; it does not create a portable software environment by itself.
- Parameter snapshots are compact and path-normalized, not a replacement for archiving the full Nextflow command and configuration.
- Candidate and enrichment previews are capped; inspect the linked full tables for complete results.
